## Implemented original experiment

`load_dataset`, `validate_dataset`, `encode_target`, `prepare_data`, `SimpleANFIS`, `choose_threshold`, and `main` provide the relevant evidence. The dataset has 1,000 rows and 20 predictors. `good` is 0, `bad` is 1. Four selected inputs are `month_duration`, `credit_amount`, `payment_to_income_ratio`, and `age`. Data inspection, unscaled histograms and correlations use the whole dataset; these are descriptive, not a fitted feature-selection method. The chosen inputs are hard-coded. `data_audit.json` records verified missingness, duplicates, observed category codes, and SHA256.

`train_test_split` first holds out 20% using seed 42 and stratification, then holds out 20% of the remainder as validation, again with seed 42 and stratification. Sizes are 640/160/200, not 600/200/200. Counts are 448/192 good/bad in fitting, 112/48 in validation, 140/60 in test. `StandardScaler` fits only the 640 fitting records. No target encoding or standardization is learned on the test set. Non-numeric selected values would be coerced to missing and removed; in the supplied data none require removal. Numeric missing target handling is fragile because integer conversion precedes removal. Validation of binary targets and missing inputs is incomplete for other datasets.

The model is a fixed-premise first-order TSK classifier, rather than the full hybrid-learning ANFIS of Jang. Each standardized input has three Gaussians, centred at training percentiles 25/50/75. Each feature's common initial width is `max(0.75 * population_std, 0.15)`; widths and centres are frozen. Antecedents form a full Cartesian product. The product t-norm gives `w_r`; normalization is `a_r = w_r / (sum(w) + 1e-10)`. Consequently `sum(a)` is not exactly one, especially when all raw firing strengths are tiny. Each consequent is linear in standardized inputs plus a bias. The logit is `z=sum(a_r*f_r)` and the score is a sigmoid with logits clipped to [-50,50]. Membership grades are not probabilities.

For four inputs there are 81 rules, 405 trainable consequent coefficients, and 24 fixed premise scalars. Consequents initialize from NumPy `default_rng(seed)` normal(0,0.05). Training uses full-batch gradient descent, learning rate 0.02, 500 epochs, weighted binary cross-entropy, weights {0:1,1:2.33}, no regularization, no validation stopping, and no premise updates. Gradients only update consequents. Per-epoch training loss is recorded before the update. Premise strengths are recomputed unnecessarily each epoch. The model is linear in its consequent coefficients conditional on frozen premises, so the unclipped BCE objective is convex in those coefficients; this does not imply good generalization or rapid convergence.

MLP uses sklearn `MLPClassifier`: hidden layers (16,8), ReLU, Adam, initial learning rate 0.001 (library default), alpha 0.0001, max_iter 1000, early stopping, internal validation fraction 0.15, patience 30, random state 42. The fitting data are oversampled to 448 good and 448 bad using replacement and the same seed. This occurs before the internal validation split, so identical source records can occur in its internal fit and stopping partitions. The external 160-row validation and 200-row test remain untouched by that resampling. The original MLP and ANFIS therefore have different imbalance treatments and different optimization/stopping protocols. Neither probability calibration nor a business cost model is implemented.

Both models select thresholds on the external validation set over 0.20–0.80 in steps of 0.01, maximizing balanced accuracy; the first maximum wins, favouring the smaller threshold on ties. The docstring's statement about maximizing F1 is incorrect; executable code maximizes balanced accuracy. Original evaluation reports accuracy, bad precision/recall/F1, ROC-AUC and confusion matrices but omits balanced accuracy, AP, specificity, training time and default-threshold comparison. All warnings are globally suppressed in original `main.py`, including convergence warnings. Its textual rules use raw feature names for coefficients that actually multiply standardized values; reports must clarify this.

## Findings requiring action

P0: The executable single-split results can be reproduced, but the supplied repeated-result claims cannot be traced to this repository. Preserve that distinction. No original RQ3 per-case explanation exists; saved rule text is a rule inventory, not an explanation. No submitted paper is available to verify exact RQ wording, word count, IEEE formatting, identities or appendix compliance.

P1: Add matched imbalance conditions, externally controlled validation, simpler baselines, per-split scores and optimization diagnostics. New scripts implement these and preserve the original experiment. Five overlapping splits support a sensitivity study, not independent replication or an unqualified paired t-test. The new protocol remains exploratory because the original test results were already inspected.

P2: Increased dimension changes both parameter count and information. New feature-ranking sensitivity restricts selection to the fitting partition and compares alternatives without selecting them on test performance. It does not establish an optimal feature subset. Integer codes for installment burden, residence, and number of credits are treated as ordered experimental inputs; equal code spacing is an assumption, not established measurement validity. `n_guarantors` has an uncertain supplied label and must not receive a substantive guarantor interpretation without a data dictionary.
